## 7. Worker

- [ ] 7.1 Implement the claim query as in D1 using SQLAlchemy Core, with `worker_id`, sorting returned rows by `(available_at, id)`. Verify tests: claim sets status, attempt count, worker, and time; rows in backoff are skipped; terminal rows are never claimed; oldest-eligible first with an id tiebreak; and two workers polling concurrently never claim the same row (threaded test, repeated).
- [ ] 7.2 Implement the lease reaper (`processing` past the lease to `unknown`, `lease_expired`, `updated_at` set), and the finalize compare-and-set (`status = 'processing' AND locked_by = :worker_id`) with a logged discard when zero rows update. Verify tests: reaper skips unexpired leases; late success before the reaper runs becomes `sent`; reaper committed first leaves `unknown` and logs the UUID and provider message id; terminal rows never change.
- [ ] 7.3 Implement the processing step: render at send time, send with the UUID as the idempotency key, and map each outcome to the state machine (accept to `sent` with time and message id; permanent to `failed`; transient to `pending` with jittered exponential backoff or `failed` at max attempts; unknown to `unknown`; render error to `failed` with `render_failed`). Verify tests with the fake provider for every outcome, the same key on a retry, backoff growth and cap, a removed template, and that an `unknown` row is never claimed again.
- [ ] 7.4 Implement the worker loop (reap, claim, process sequentially, sleep when idle) and graceful shutdown on SIGTERM and SIGINT so the in-flight send finishes within the provider deadline. Add the worker entry point. Verify an integration test that runs the loop in a thread against the fake provider and drains a queue, and a test that a shutdown signal stops claiming without abandoning the in-flight row.
- [ ] 7.5 Add logging that never contains recipients, options, or provider response text, with UUID-keyed lines. Verify a test capturing logs across a failing provider that echoes a phone number and asserting the number is absent.
